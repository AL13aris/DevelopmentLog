## 개발 일지 & TIL

**새 게임·항구 복원과 수면 이동·해상 승선**

[[00_캡스톤 제작 기록 - 2026년 9월~11월|← 날짜별 제작 기록 목차]]

### 기본 정보

- 날짜: 2026-09-30 (한국시간)
- 프로젝트: Starizon Light / GameCapstone
- 기록 성격: 구현·일부 사용자 확인

### 오늘 한 작업

- **코드 구현** — PrepareNewGame(FString& FailReason)을 추가했다. 필요한 서브시스템과 기존 저장 삭제 성공을 확인한 뒤 레벨·경험치, 인벤토리(골드 포함), 퀘스트, 마지막 항구, 게임 날짜와 메인 퀘스트 단계를 초기화한다.
- **초기화 순서** — 모든 진행 상태를 먼저 초기화한 후 UI 알림을 보낸다. 날짜 초기화는 상인 리필 이벤트를 일으키지 않으며, 함수 성공 뒤에만 시작 화면에서 메인맵을 열도록 계약을 정했다.
- **코드 구현** — 이어하기에서 LastPortID와 일치하는 항구로 기존 캐릭터와 배 한 척을 옮기는 복귀 경로를 추가했다. 맵 준비 후 콜백 및 최대 10초의 재시도 처리를 연결했다.
- **저장 보호** — 항구 복귀가 끝나기 전 입항·상인 방문·SetLastPort·자동 저장을 보류해 기본 Kingdom 배치가 로드한 항구 정보를 덮어쓰지 않게 했다. 복귀 성공 후 실제 겹침을 다시 검사한다.
- **배치 도구** — PlayerReturnBox/PlayerReturnDirection과 ShipReturnBox/ShipReturnDirection을 추가해 에디터에서 복귀 위치·공간·방향을 볼 수 있게 했다. 캐릭터는 박스 아래면 중앙, 배는 박스 중심을 기준으로 한다.
- **진단** — 복귀 실패를 바닥 미검출, 시작부터 장애물 겹침, 보행 불가 면으로 구분하고 Actor/Component 등 진단 정보를 표시했다. SaveGameToSlot 반환값에 따른 성공·실패 로그도 추가했다.
- 기존 PlayerCharacter 파일 안에 UPlayerSurfaceMovementComponent를 추가해 WaterBody 감지 구간에서 PhysSwimming으로 수면 이동을 처리하도록 구현했다.
- 실제 WaterBody 충돌 범위와 유효한 수면 조회·제외 영역을 검사하고, 기존 WASD·카메라 입력과 캡슐 충돌 이동을 재사용했다. 얕은 보행 바닥은 Walking, 물 밖은 Falling으로 돌아가게 했다.
- 숨김·충돌 해제·Movement None인 탑승 캐릭터와 항구 복원 대기 상태는 수면 자동 전환에서 제외했다. 수영 중 상호작용은 CanBoardFromWater 후보를 통해 기존 승선 인터페이스로 연결했다.
- 이어하기 복원 중에는 MerchantNPC의 초기 배 겹침 조회와 입항 이벤트 두 경로 모두 제안을 시작하지 못하도록 차단했다.
- PlayerShipPawn에 WaterBoardingArea를 추가하여 수면의 캐릭터 캡슐과 배 주변 박스의 실제 겹침을 입력 시 검사했다.
- 수영 상태, 비어 있는 배, 유효 선체 충돌, 항구 복원 대기 여부와 장애물 가림을 확인해 해상 탑승 후보를 결정했다.
- 해상 탑승 전에 DisembarkPoint의 안전한 갑판을 검사하고, 물에서 탑승했음을 기록해 하선할 때 물속의 이전 발 위치 대신 갑판 마커로 복귀하게 했다.
- 조종 전환이 실패하면 캐릭터 숨김·충돌·Tick·이동 모드·이동 Base를 되돌리도록 보완했다.

### 발생한 문제 & 대응

- OpenLevel만 호출하면 GameInstance와 그 서브시스템의 이전 진행이 남아 새 게임 초기화가 되지 않았다. ResetSaveData도 저장 파일 삭제만 수행해 충분하지 않았다.
- 기존 이어하기는 LastPortID 데이터를 읽어도 실제 캐릭터·배를 옮기지 않아 기본 배치의 Kingdom 입항이 다시 발생할 수 있었다.
- 사용자 복귀 시도에서 배의 Controller 보유, Return Points Configured 미설정, Kingdom 바닥 검사 실패가 순서대로 확인됐다. 이를 실제 복귀 성공으로 기록하지 않았다.
- PortArea의 입항 이벤트만 막으면 상인의 BindHomePort 초기 오버랩 조회가 복원 전 기본 항구의 방문·LLM 요청을 먼저 시작할 수 있었다. HasShipInHomePort와 HandlePortEntered 양쪽에서 복귀 대기 상태를 확인하도록 했다.
- 바다에서 탑승한 캐릭터의 이전 발 위치를 그대로 쓰면 하선 시 다시 물로 돌아갈 수 있어, 해상 탑승과 일반 갑판 탑승 경로를 나눴다.

### 확인 결과와 검증 범위

- **사용자 로그 확인** — 당일 [NewGame] Prepared 이후 LV_MainMap 진입, BP_StarizonGameMode 선택, Kingdom과 Island1 입항이 기록됐다. 새 게임 API 실행 증거이며 모든 초기화·실패 분기 통과 증거는 아니다.
- **정적 확인** — 맵 콜백 순서, 충돌 질의, 저장 보호와 입항 재개 순서를 검토했다.
- **미검증** — 새 복귀 박스/진단 코드의 전체 빌드·배치·실제 이어하기 복귀 성공은 당일 기록상 대기였다.
- Water/이동 API와 선언·호출 관계, 변경 범위·인코딩을 정적으로 확인했다. 이 날짜의 수영, 해상 승선과 복귀 후 상인 방문은 사용자 빌드·PIE 확인 대기다.
- Use Custom Disembark Point 설정 안내 후 사용자가 '확인했어 잘되네'라고 하여 지정 갑판 하선을 확인했다.
- 수면 이동·해상 재탑승·해안 복귀·범위 밖 거부의 전체 개별 테스트가 완료됐다고 확대하지 않는다.

### 당시 남은 문제 / 미확인 사항

- 복귀 실패 후에는 기존 저장을 보호하려고 보류 상태를 유지한다. 배포용 실패 안내 UI와 완전한 입력 잠금은 아직 없었다.
- 복귀 대상 항구는 고유 PortID, 단일 미소유 플레이어 배, 올바른 Query Collision과 보행 가능한 바닥이 필요하다.
- 이미 잘못된 항구 ID로 덮인 과거 저장을 이 코드만으로 복원할 수는 없다.
- 상인 재고와 메인 목표 단계 저장, 시작 자금·아이템 지급 규칙은 이 단계에 포함되지 않았다.
- 잠수·익사·수영 애니메이션·침몰 후 구조와 높은 부두로 기어오르기는 범위 밖이다.
- Water 충돌이 Query 가능해야 하며 저장된 BP의 이동 설정이 C++ 기본값을 덮어쓸 수 있다.
- 실제 복원 항구 방문이 한 번만 등록되는지 별도 시험이 필요하다.
- WaterBoardingArea와 DisembarkPoint는 실제 선체 길이·갑판 충돌에 맞는 BP 배치가 필요하다.

### 다음 작업 — 당시 기준

- 에디터 종료 후 전체 빌드·재시작, 각 항구의 PlayerReturnBox와 ShipReturnBox 배치 및 Return Points Configured 설정을 확인한다.
- Island1 저장→종료→로비 이어하기→Island1 복귀, Kingdom 복귀, 이동·승선·출항·재입항을 시험한다.
- 저장 없음, 삭제 실패, 잘못된 복귀 지점·충돌·중복 PortID 등 실패 경로에서 기존 진행 보호를 확인한다.
- 사용자 전체 빌드 뒤 육지 이동→바다 진입→수면 유지·이동→얕은 해안 보행→해상 승선→하차를 시험한다.
- 로비 이어하기에서 복귀 전 잘못된 상인 요청이 없고 복귀한 항구의 방문만 시작되는지 확인한다.
- 수면에서 접근→탑승→조종→갑판 하차→재승선과 범위 밖/장애물 뒤 거부를 비교한다.

### 오늘의 기술 정리 (TIL)

- 맵 전환과 GameInstance 진행 초기화는 별개다. 새 게임은 초기화 성공 여부를 확인한 뒤 맵을 열어야 한다.
- 저장된 데이터 적용, 월드 액터 위치 복원, 입항·자동 저장 재개에는 순서가 있다.
- PlayerReturnBox의 아래면 중앙은 발 위치이고 Box Extent는 반크기다. 공간 가이드(NoCollision)와 실제 바닥 충돌은 다른 역할이다.
- 수면 높이 조회만으로 물 영역을 판정하면 육지나 경계 밖도 바다처럼 처리할 수 있어 WaterBody의 실제 충돌 영역과 제외 영역을 함께 검사해야 한다.
- 저장 복원 보호는 이벤트뿐 아니라 초기 상태 조회에도 일관되게 적용해야 한다.
- 회수/탑승 범위용 형상과 실제 물리 충돌은 목적이 다르다. 명시적 형상 검사로 감지 범위를 조절하면서 기존 선체 물리를 유지했다.
- 수면 탑승 후 하선 위치는 안전한 갑판 기준으로 별도 관리해야 한다.
