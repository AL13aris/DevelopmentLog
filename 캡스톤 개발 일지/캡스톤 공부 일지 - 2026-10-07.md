### 기본 정보

- 날짜: 2026-10-07 (한국시간)
- 프로젝트: Starizon Light / GameCapstone
- 기록 성격: UI 정리·팀원 보고·통 설계

### 오늘 한 작업

- 사용자에게서 팀원 UI 작업 7개가 전달됐다: MainDialogue의 FDialogueLine 참조 복구, MainHUD 날짜·의뢰·상호작용 배치, QuestSlot의 패널 크기와 '밀 x10' 제목, QuestTracker의 0.5초 갱신, Settings의 초기화 확인·로비 복귀, InteractPrompt 조건부 표시, Trade의 재고·인벤토리·닫기 연결. 이는 팀원 완료 보고를 전달받은 내용이며 AI가 에셋과 실행을 직접 검증한 결과는 아니다.
- 퀘스트 트래커의 표시 방법과 연결 상태를 검토했지만 사용자가 나중 연결할 항목으로 미뤘다.
- ESC 메뉴의 상인·전투 레벨 표시를 세로 배치하려고 레벨 컨테이너를 Vertical Box로 바꾸고 Border의 실제 크기를 조정했다.
- 사용자가 레이아웃을 맞췄다고 보고한 뒤 보유 골드 추가와 전투 레벨·상인 레벨 설명 텍스트 추가를 진행했다.
- 골드가 증가하면 텍스트 박스 폭이 커져 왼쪽으로 이동하는 현상을 확인했다. 수량 변화에 따른 텍스트 정렬 문제를 다음 점검 대상으로 남겼다.
- 해상 통 회수·절차 생성 설계 v1 문서를 작성했다. 통이 배를 밀지 않으며 근처에서 명시적 상호작용으로 회수되는 방향을 정리했다.
- 해역의 배치·내용물을 시드로 결정하는 규칙과 배 주변 구역만 실제 활성화하는 관리 방식을 함께 사용하는 설계를 기록했다.
- 고정 후보 번호 기반 통 ID, 내용물 최초 추첨, 육지·부두·얕은 수면 제외, 통 사이 최소 간격과 소진 상태 보존을 구현 기준으로 정리했다.

### 발생한 문제 & 대응

- 레벨 컨테이너를 세로로 바꾼 후 텍스트와 Border 크기·위치를 함께 맞출 필요가 있었다.
- 보유 골드 숫자가 길어질 때 텍스트 영역 폭이 늘어나 왼쪽으로 이동했다.

### 확인 결과와 검증 범위

- 한국시간10월7일01:00 사용자가 '일 단 맞췄고 이제 골드 추가를 하자'라고 레이아웃 조정 결과를 확인했다.
- 한국시간10월7일01:17 사용자가 골드 증가에 따른 텍스트 박스 확장을 보고했다. 골드 표시를 시험하고 있음을 확인할 수 있으나 정확한 바인딩·저장 후 복원·보상 반영 전체 검증은 아니다.
- 상인·전투 레벨 라벨 추가 요청과 기존 그래프 검토는 확인되지만, 두 라벨의 최종 표시 완료를 명시한 발화는 당시 대화에서 확인하지 못했다.
- 문서 작성일은 10월7일이며 실제 통 코드·Water 부력 적용은 10월10일에 별도로 기록되어 있다.
- 현재 문서는 10월10일에 갱신되어 있어 모든 현황 문장을 10월7일 구현으로 간주하지 않는다.

### 당시 남은 문제 / 미확인 사항

- 팀원 7개 위젯 작업의 구현일 자체가10월7일임을 입증한 것은 아니다.10월7일은 이 채팅에 작업 내역이 전달된 날짜다.
- 퀘스트 트래커 연결·골드 정렬·최종 레벨 라벨·ShipRank/내구도 등의 남은 항목을 완료로 기록하지 않는다.
- 구역 크기·밀도·확률·수량·활성 거리와 저장 정책의 세부 수치는 당시 확정되지 않았다.

### 다음 작업 — 당시 기준

- 골드 숫자의 자리수가 늘어나도 레이아웃이 유지되도록 영역 크기와 정렬을 점검한다.
- 상인·전투 레벨 설명 텍스트의 최종 배치와 표시를 확인한다.
- 미룬 퀘스트 트래커 연결은 이후 HUD 통합 시 검증한다.
- 단일 통 회수부터 구현하고 기본 부유·지급을 확인한 뒤 절차 생성과 랜덤 보상을 연결한다.

### 오늘의 기술 정리 (TIL)

- 가로·세로 컨테이너를 바꾸면 자식 정렬뿐 아니라 부모 Border가 차지하는 실제 영역도 함께 확인해야 한다.
- 숫자 텍스트의 내용에 따라 원하는 폭이 달라지므로 증가하는 골드 표시는 자리수 변화까지 고려해 배치해야 한다.
- 다른 팀원의 구현 보고와 현재 프로젝트에서 직접 실행해 확인한 상태는 구분해서 기록해야 한다.
- 절차 생성은 '어디에 무엇을 놓을지', 주변 활성화는 '언제 실제 액터를 만들고 갱신할지'의 문제로 분리할 수 있다.
- 고정 후보 번호와 독립 난수 흐름은 후보 탈락이나 재방문 때문에 다른 통의 보상이 바뀌는 문제를 줄이는 설계 기준이다.
