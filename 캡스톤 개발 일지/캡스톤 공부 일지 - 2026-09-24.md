### 기본 정보

- 날짜: 2026-09-24 (한국시간)
- 프로젝트: Starizon Light / GameCapstone
- 기록 성격: 구현·사용자 UI·로그 확인

### 오늘 한 작업

- MerchantNPC를 HomePortID에 해당하는 PortArea 입·출항 이벤트에 연결하고, 입항마다 미수락 제안을 준비·보관하도록 구현했다. 하선으로 Pawn이 바뀌어도 배가 항구에 남으면 같은 방문을 유지한다.
- 자동 수락을 제거하고 AcceptCurrentOffer/RejectCurrentOffer를 분리했다. 화면에 표시한 QuestID와 VisitSerial을 검증하며, 같은 방문에서 거절한 제안도 보관한다.
- 약한 참조, 요청 번호, 방문 번호와 제한 시간으로 출항·종료 뒤의 오래된 비동기 응답을 무시하도록 했다. 시간 초과 처리는 UI 대기를 끝내며 HTTP 자체 취소는 구현하지 않았다.
- BaseNPC에 OnDialogueWidgetCreated 이벤트와 ActiveDialogueWidget 참조를 추가하고, 위젯 생성 → 상인 참조 전달 이벤트 → AddToViewport 순서를 마련했다. GetCurrentQuest를 BlueprintCallable로 공개했다.
- Ready 로그에 Fetch 요구·보상과 Sell 지급·비용 상세를 복구했다. WBP_QuestProposal1은 MerchantRef 조회, OnOfferChanged 갱신, 표시 ID·방문 번호, 수락·거절 및 커서/닫기 흐름으로 연결했다.
- UpdateQuestDetails에서 구조체의 품목·수량·골드를 표시하도록 배선을 정리하고, 실제 화면·로그와 미확인 항목을 Blueprint_WorkLog.md에 기록했다.
- 상인 자동 수락 제거에 맞춰 Graft의 저장된 설명과 Context 지도를 재검토했다. 설명의 기준 해시와 실제 소스 변경을 함께 확인했다.

### 발생한 문제 & 대응

- 기존 UI는 ActiveQuests 증가와 마지막 항목을 감시해 수락 전 제안 캐시와 맞지 않았고, Bad cast와 미연결 타이머 핀이 있었다.
- 자동 수락 분리 이후 Ready 로그에서 상세 수량과 보상이 빠졌지만 실제 퀘스트 데이터는 유지되고 있었다. 공통 응답 로그를 복구했다.
- NPC가 눕는 문제는 사용자가 Simulate Physics 해제로 해결했다고 보고했다. 정확한 컴포넌트 최종값은 미확인이다.
- UMG 텍스트에 Text Render Component용 SetText와 위젯 참조의 ToText(Object)를 잘못 연결한 부분을 올바른 UMG SetText(Target=텍스트 위젯, InText=FormatText 결과)로 안내·수정했다.

### 확인 결과와 검증 범위

- 사용자 PIE 화면에서 대화창과 예/아니오 표시를 확인했고, 로그에 Ready → Declined → Declined → Accepted가 기록됐다. 이후 stale/unavailable 경고는 이미 수락한 제안을 사용자가 의도적으로 다시 수락한 결과다.
- 첫 방문의 Loading model/503 이후 재시도·템플릿 폴백, 재입항 Visit=2의 실제 LLM 응답을 확인했다. 양쪽 Ready에 밀 17개와 골드 136개 조건이 출력됐다.
- 수락의 save requested는 확인됐지만 디스크 기록·재실행 복원까지 확인한 것은 아니다. Blueprint 배선은 사용자 스크린샷 근거이며 AI가 에셋을 수정하거나 PIE를 실행하지 않았다.

### 당시 남은 문제 / 미확인 사항

- 수락 완료 안내와 X 버튼은 사용자가 다음 날로 미뤘다. 구독 해제, 닫기 후 조작 복귀, Sell 상세, 빈 데이터 초기화, 최종 표시값 일치는 미검증이었다.
- 상인 재고 저장, 방문 캐시의 영속화, 모델 준비 완료 대기/요청 큐와 실제 HTTP 취소는 이 단계에 포함되지 않았다.
- 항구·상인 동적 생성 및 스트리밍 재연결은 범위 밖이며, 여러 항구·요청 중 출항·늦은 응답·저장 복원 회귀 시험이 남았다.

### 다음 작업 — 당시 기준

- 최신 UI에서 제출·보상·재고와 저장/로드를 다시 시험한다.

### 오늘의 기술 정리 (TIL)

- 퀘스트 생성, 화면 조회, 명시적 수락은 서로 다른 상태 전이로 분리해야 한다.
- 버튼은 클릭 시 새 ID를 읽는 대신 화면을 채울 때 보관한 QuestID·VisitSerial을 전달해야 오래된 UI 입력을 거절할 수 있다.
- 서버 프로세스가 시작된 것과 모델이 요청을 받을 준비가 된 것은 다르며, 수량과 보상은 LLM 대사 파싱이 아니라 구조체 데이터로 표시한다.
