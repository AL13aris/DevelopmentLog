### 발생한 문제 & 해결 방법

### **문제 상황**
- W/S 키를 눌러도 이동이 전혀 안 됨(A/D는 정상)
- S를 누르면 후진이 아니라 전진함
- 마우스로 시점 상하 회전 시 방향이 반대로 느껴짐
- NPC에게 가까이 가도 상호작용이 감지되지 않음(콜리전이 서로 밀어냄)
- 상호작용 버튼을 짧게 눌러도 로그(`ZoomToNPC 호출됨`)가 수십 번씩 반복 출력됨
- Perforce 서밋 시 "Merges still pending" 에러로 체크인 실패, `DefaultEngine.ini`에서 병합 충돌 발생(`GameInstanceClass` 값이 서버/로컬에서 다름)
- 병합 도구 사용 중 실수로 두 값을 모두 남겨 같은 키가 두 줄로 중복되는 상황 발생

### **해결 방법**
- W/S 무반응: Axis2D 입력에서 키보드 기본값이 X축에 들어간다는 것을 확인, W/S에는 Swizzle(YXZ) 모디파이어를 추가해 Y축으로 옮기도록 수정. A/D는 X축 그대로라 Scalar만으로 충분했음
- S가 전진하는 문제: Swizzle만으로는 값의 부호(+1)가 그대로 유지되어 W와 똑같이 동작 — S에 Negate 모디파이어를 추가로 적용해 해결
- 마우스 상하 반전: `DoLook()`에서 `AddControllerPitchInput(Pitch)`를 `AddControllerPitchInput(-Pitch)`로 부호 반전
- NPC 상호작용 미감지: `InteractionDetector`(USphereComponent)의 콜리전 프로필이 기본값(Block)으로 남아있어 다른 콜리전과 물리적으로 충돌 — `SetCollisionProfileName(TEXT("OverlapAllDynamic"))` 추가로 겹침만 감지하도록 수정. 반지름도 150으로 확대(기존값이 캡슐 콜리전보다 작았음)
- 로그 반복 출력: `InteractAction` 바인딩이 `ETriggerEvent::Triggered`(누르고 있는 동안 계속 발생)로 되어 있던 것이 원인 — `ETriggerEvent::Started`(누르는 순간 1회)로 변경해 해결
- Perforce 병합 충돌: `DefaultEngine.ini`의 `GameInstanceClass`가 서버(StarizonGameInstance, 최신)와 로컬(엔진 기본값)에서 다르게 되어 있던 것이 원인. P4Merge에서 서버 쪽 값만 남기도록 정리(엔진 기본값 줄 삭제) 후 재서밋하여 해결

### **배운 점**
- Enhanced Input에서 키보드 입력은 기본적으로 축의 첫 번째 자리(X)에 값을 넣는다는 것, 이를 다른 축으로 옮기려면 Swizzle 모디파이어가, 방향을 반전하려면 Negate 모디파이어가 필요하다는 것 — 이 둘의 역할이 명확히 다르다는 걸 실제 삽질을 통해 체감
- 콜리전 컴포넌트를 만들 때 반지름/모양뿐 아니라 "콜리전 프로필"(Block/Overlap 여부)도 반드시 확인해야 한다는 것 — 기본값이 항상 우리가 원하는 동작(겹침 감지)이 아닐 수 있음
- `ETriggerEvent`의 종류(`Triggered`/`Started`/`Completed`)를 상황에 맞게 골라야 하며, 잘못 고르면 로직 자체는 맞아도 "몇 번 실행되는지"가 완전히 달라진다는 것
- Perforce에서 같은 설정 파일(ini)에 서로 다른 두 팀원이 각자 다른 값을 넣으면, 병합 도구가 두 값을 모두 남겨버릴 수 있어 결과물을 직접 눈으로 검증해야 한다는 것 — 자동 병합 결과를 그대로 믿으면 안 됨

### 위험 요소 / 리팩토링할 부분
- `DefaultEngine.ini`의 `GameInstanceClass` 설정이 이번처럼 계속 팀원 간 충돌 소지가 있음 — 앞으로 이 파일을 수정할 때는 팀 채널에 미리 공지하는 습관이 필요할 듯

### 오늘 배운 점 (TIL)
### **알게 된 내용:**
- Enhanced Input의 Modifier 종류(Swizzle, Negate, Scalar)가 각각 하는 일이 다르다는 것 — Scalar는 값 자체를 조정, Swizzle은 값이 들어가는 축 자리를 바꿈, Negate는 부호를 반전
- `SetCollisionProfileName()`으로 미리 정의된 콜리전 설정 묶음을 한 번에 적용할 수 있다는 것, `OverlapAllDynamic`이 "겹침 감지 전용" 프리셋이라는 것
- Perforce Resolve 화면에서 "Differences from base: 0"이 양쪽 다 떠도 실제로는 서로 다른 값이 충돌할 수 있다는 것(단순 공백/줄바꿈 차이가 아닌 진짜 값 차이인 경우)
### **헷갈렸던 점**
- Swizzle을 추가했는데도 S가 여전히 전진해서 처음엔 원인을 못 찾았음 — Swizzle(축 이동)과 Negate(부호 반전)가 별개의 역할이라는 걸 명확히 이해하고 나서야 해결됨
- 병합 도구가 충돌을 "자동으로 해결"해준 것처럼 보였는데 실제로는 두 값을 그냥 다 남겨놓은 상태였음 — 병합 결과를 검증 없이 그대로 받아들이면 안 된다는 걸 체감
