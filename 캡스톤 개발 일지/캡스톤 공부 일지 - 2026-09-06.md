### 발생한 문제 & 해결 방법

### **문제 상황**
1. 함선 탑승 후 함포 조준키·발사키를 눌러도 아무 반응이 없어 보임.
2. 포탄이 발사돼도 화면에 안 보임.
3. `PlayerShipPawn.cpp` 컴파일 에러 `C4458: 'bHidden' 선언은 클래스 멤버를 숨깁니다`.
4. 브로드사이드 5발이 총구 근처에서 서로 부딪혀 터지고 궤도가 튐.
5. 포탄이 중간까지 날아가다 사라짐.
6. 조준 카메라를 어떻게 잡을지 계속 안 맞음 — 파라미터로 했다가, 오버헤드로 했다가, 컴포넌트 배치로.

### **해결 방법**
1. 진단 로그를 각 지점(입력 바인딩, `FireAimedCannon` 진입, `FireCannonLeft/Right`의 early-return 조건별, 스폰 좌표)에 박아 PIE 로그로 추적. 결과: **입력·발사·조준 전부 정상 동작 중**이었음. 조준은 궤적 위젯이 없어 화면에 안 보였던 것뿐(카메라가 멈추는 건 설계상 정상).
2. 로그로 `Spawn 성공 at (x,y,z)` 확인 → 스폰은 됨. 원인은 (a) `BP_Cannonball`의 `ProjectileMesh`에 메시 미할당(투명) (b) 스폰 지점이 선체에 가까워 자기 배에 즉시 충돌 → `OnHit`의 무조건 `Destroy()`. (b)를 코드로 수정.
3. `AActor`에 `bHidden` 멤버가 이미 있음. 파라미터명을 `bShouldHide`로 변경(헤더+cpp).
4. 스폰한 포탄들을 배열로 모아 서로 `IgnoreActorWhenMoving(Other, true)` 교차 등록 → `UProjectileMovementComponent`의 이동 sweep이 형제 포탄을 무시 → 충돌·궤도 튐 없음. `OnHit`에도 `OtherActor->IsA<ACannonballProjectile>()` 가드 추가(2차 방어).
5. `LifeSpanExpired` 로그로 "수명 만료"임을 확인. 원인: 생성자에서 `InitialLifeSpan = LifeSpanSeconds`가 **C++ 기본값 5를 캡처**해버려, BP에서 `LifeSpanSeconds`를 고쳐도 소용없었음. `BeginPlay`에서 `SetLifeSpan(LifeSpanSeconds)` 호출로 옮김.
6. 사용자 피드백을 3번 반영: (1) "파라미터 말고 그냥 이동" → 오버헤드 카메라 (2) "내려다보는 게 아니라 쏘는 방향" → 발사 방향 블렌드 (3) "뷰포트 배치 말고" → 파라미터 → "차라리 화살표 컴포넌트로" → `UArrowComponent` 마커. 최종은 화살표 하나 + 좌현 자동 미러.

### **배운 점**
- **UE 컴파일 에러가 나면 "가장 먼저 나온 에러"를 보고, 엔진 멤버 이름 충돌(`bHidden`, `Instigator`, `TakeDamage` 등)부터 의심.** 이번 프로젝트에서 세 번째 겪음.
- **UPROPERTY 값을 생성자에서 다른 변수/상태에 "복사"하면, 이후 BP나 인스턴스가 그 UPROPERTY를 편집해도 반영 안 됨.** 초기화가 필요하면 `BeginPlay`나 `PostInitializeComponents`에서. (`InitialLifeSpan` = `LifeSpanSeconds`, `AMerchantNPC`의 임시 TMap과 같은 부류의 실수)
- 물리 이동 중 특정 액터와의 충돌만 빼려면 `UPrimitiveComponent::IgnoreActorWhenMoving`. 발사체가 자기 발사자/형제 발사체를 무시할 때 표준.
- "동작 안 함"처럼 보여도 로그를 촘촘히 박으면 대개 "동작은 하는데 안 보이는 것"이거나 "한 조건에서 조용히 return"인 경우가 많음. `if (A || B || C || D) return;` 형태는 어느 조건인지 안 나오므로, 디버깅 땐 조건을 분해해서 각각 로그.

### 오늘 배운 점 (TIL)
### **알게 된 내용:**
- **`UArrowComponent`** — 에디터 뷰포트에 색깔 화살표로 그려지는 `USceneComponent`. "위치 + 방향"을 디자이너가 기즈모로 잡게 하는 마커로 표준. `bHiddenInGame` 기본 `true`라 게임 중엔 안 그려지지만 컴포넌트 자체는 런타임에 존재 → 트랜스폼을 읽을 수 있음. `#if WITH_EDITORONLY_DATA` 안에서 `ArrowColor`/`ArrowSize` 설정.
- **`FMath::VRandCone(Dir, HalfAngleRad)`** — 주어진 방향을 중심으로 원뿔 안의 랜덤 단위벡터. 탄퍼짐(스프레드)에 딱. `.Rotation()`으로 FRotator 변환.
- **`FQuat::Slerp(A, B, Alpha)`** — 두 회전 사이 구면 보간. `FRotator`를 `FMath::Lerp`로 성분 보간하면 wraparound 문제 생기므로 카메라 회전 블렌드엔 Slerp.
- **`UPrimitiveComponent::IgnoreActorWhenMoving(AActor*, bool)`** — 이 컴포넌트가 sweep으로 이동할 때 특정 액터와의 충돌을 무시. `MoveIgnoreActors`에 추가하는 것과 같음. 발사체 ↔ 발사자/형제 발사체.
- **라인트레이스**: `GetWorld()->LineTraceSingleByChannel(OutHit, Start, End, ECC_Visibility, QueryParams)`. `FCollisionQueryParams`에 `AddIgnoredActor(this)`. `#include "CollisionQueryParams.h"`, `Engine/World.h`.
- **`AActor::LifeSpanExpired()`** — `virtual`. `SetLifeSpan()`/`InitialLifeSpan` 타이머 만료 시 호출됨(기본 구현이 `Destroy()`). override해서 로그 등 넣고 `Super::` 호출.
- `SetLifeSpan(N)`은 `InitialLifeSpan`을 덮어씀. `BeginPlay`에서 부르면 BP가 편집한 UPROPERTY 값을 반영할 수 있음.
### **헷갈렸던 점**
- **조준 시 카메라가 안 움직이는 게 버그인 줄** — 사실은 설계대로였음(조준 모드는 카메라를 멈추고 마우스 룩을 조준 오프셋으로 돌림). 궤적 위젯이 없어 화면에 피드백이 없었을 뿐. "안 움직인다 = 고장"으로 넘겨짚었다가 로그 보고 정정.
- **`InitialLifeSpan = LifeSpanSeconds`가 왜 안 먹히는지** — 생성자는 C++ 기본값으로 실행되고, BP 프로퍼티 오버라이드는 그 다음에 적용됨. 생성자에서 이미 `InitialLifeSpan`에 5를 넣었으니 BP가 `LifeSpanSeconds`를 12로 바꿔도 `InitialLifeSpan`은 그대로 5. 이 패턴(생성자에서 UPROPERTY를 다른 상태로 캡처)은 이 프로젝트에서 이미 `AMerchantNPC` 임시 TMap으로 한 번 데었던 것.
- 포탄이 "총구에서 터진다" vs "중간에 사라진다"를 같은 문제로 착각. 앞은 근접 충돌(자기 배·형제 포탄), 뒤는 수명 만료 — 원인이 완전히 다르고 로그로 구분해야 했음.
**예제 코드 또는 상황**
