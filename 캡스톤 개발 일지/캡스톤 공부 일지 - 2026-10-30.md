- 날짜: 2026-10-30 (한국시간)

- 기록 성격: 별도 플러그인 구현·검증 기록

### 오늘 한 작업

- **구현·별도 플러그인** — UE 5.7.4의 FFTPlugin 프로젝트에 StarizonOcean을 구성하고, 해석적 사인파 높이·노멀을 Water 조회와 기본 동기 부력에 연결했다. 기존 Water 파도 객체는 소유권을 확인해 복구하도록 했다.
- **구현** — 월드별 공통 바람 Subsystem, 바람 소스·프리셋·진단 소비자를 추가했다. 풍속 단위와 풍향 기준, 무풍·방향 전환, 소스 중복 및 월드 분리 규칙을 명시했다.
- **수정·빌드 확인** — 사용자 Visual Studio 개별 컴파일의 C4150을 조사하고, 전방 선언 내부 모델을 가진 UObject의 FVTableHelper 생성자를 모델 정의가 보이는 cpp에 구현했다. 같은 UBA/adaptive 옵션의 Editor·Game 빌드와 기존 시험을 다시 통과했다.
- **구현** — GPU Compute Shader/RDG에서 사인파 높이·기울기 격자를 계산하고 수면 재질의 WPO·노멀에 전달했다. 기존 CPU 사인파를 수치 비교 기준으로 유지했다.
- **구현** — 비동기 GPU Readback과 불변 Snapshot, 4개 슬롯의 게시 규칙을 추가했다. CPU 복사가 완료된 프레임의 텍스처와 Snapshot을 함께 게시하여 화면과 물리 조회가 같은 수면 데이터를 쓰도록 했다.
- **구현** — Readback 수면을 명시적 WaterBodyOcean과 동기 Buoyancy 소비자에 연결하고, 첫 결과 전 무효·지연된 결과 유지·재설정·PIE 종료·기존 파도 복구를 처리했다.
- **검증 기록** — Editor/Game 빌드, 자동 시험, 반복 PIE, Win64 Development Cook/Stage/Archive와 기존 패키지 실행 기록을 남겼다. 당일 Readback 단계 최종 요약은 한국시각 23:35로 기록되어 있다.

### 발생한 문제 & 대응

- 사용자 Visual Studio의 C4150은 전방 선언 타입과 UObject 생성자 정의 위치 문제였으며, 앞선 unity 빌드에서 누락이 드러나지 않았다.
- 초기 GPU 수면 재질이 C++ soft 경로만 가져 Cook에서 누락됐다. 명시적 UObject 참조로 변경한 뒤 재저장·재패키징·실행을 확인했다.
- 사인파 초기 시험 큐브는 부력 계수가 낮아 충분히 뜨지 않았다. 해당 시험 물체 설정을 조절했으며 실제 선박에 같은 값을 보장하지 않는다.

### 확인 결과와 검증 범위

- **기존 자동 시험 산출물 확인** — Readback 단계 자동 시험 10/10 성공, 실패 및 테스트 경고 0. 표시 텍스처와 Snapshot의 RGBA 일치, 홀수 폭 RowPitch, 지연·재설정·월드 분리·종료 수명 등을 검사했다.
- **기존 빌드·패키지 산출물 확인** — Editor/Game 빌드와 Development Cook/Stage/Archive 성공. 최종 Cook 오류·경고 0, 패키지 실행 정상 종료가 기록돼 있다.
- **기존 실행 산출물 확인** — Readback 패키지를 고정 60Hz로 시뮬레이션 20초 실행했고 5·10·15·20초 관찰에서 Water 겹침 1개와 4/4 폰툰을 기록했다. 이는 수면 조회 및 시험 큐브 관찰 근거다.
- **사용자 확인 범위** — README에는 사용자의 바람 단계·GPU 사인파 단계 정상 확인이 기록돼 있다. 초기 사인파 PIE 로그도 확인됐지만 Baseline의 큰 파도에서는 폰툰이 일시적으로 0/4였으므로 항상 안정적이었다고 기록하지 않는다.

### 당시 남은 문제 / 미확인 사항

- 고정 60Hz는 시뮬레이션 시간 진행 조건이며 실시간 60FPS 달성이나 성능 벤치마크를 뜻하지 않는다.
- Readback 단계까지는 유한 사인파 패치이며, FFT 단계는 10월 30~31일에 걸쳐 진행됐다. 당일 완료된 것으로 모든 후속 FFT·LOD 기능을 소급하지 않는다.
- 패키지에는 별도 선택 플러그인 WaterAdvanced의 Grid2D_OceanPatch 누락 경고가 남아 있다. 테스트 경고 0·Cook 경고 0과 런타임 경고를 구분한다.
- 원본 GameCapstone은 수정하지 않았고 본게임·실제 선박 이식, Shipping, 다른 GPU와 장시간·실시간 성능은 미검증이다.

### 다음 작업 — 당시 기준

- Readback 기반을 유지하면서 Phillips 스펙트럼과 GPU 역 FFT로 확장하고, 독립적인 CPU 기준과 수치 비교를 진행한다.
- 풍속·풍향을 FFT 입력에 연결하고 수면 외형·넓은 해역 표시를 단계적으로 확장한다. 해당 후속 구현은 10월 31일 기록과 구분한다.

### 오늘의 기술 정리 (TIL)

- GPU 계산 결과와 CPU 물리 조회는 같은 완료 프레임으로 묶어야 화면·부력의 기준이 어긋나지 않는다.
- Readback 비동기 처리와 Water 물리의 동기 실행 여부는 별개이며, 같은 시스템의 서로 다른 단계로 다뤄야 한다.
- unity 빌드 성공만으로 전방 선언·개별 번역 단위의 타입 완전성 문제가 검증되지는 않는다.
- 정지 화면, 수치 조회 PASS, 실제 물체 움직임과 성능은 서로 다른 근거이므로 결과를 분리해 기록한다.
