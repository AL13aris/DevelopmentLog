### 발생한 문제 & 해결 방법

### **문제 상황**
- `OnInteract` 정의 시 LNK2005(중복 정의) / LNK1169
- 이름을 고친 후에도 C2084("이미 본문이 있음") 에러가 같은 위치에서 반복
- `PlayerCharacter.cpp`에서 `USpringArmComponent`/`UCameraComponent`/`USphereComponent`가 "정의되지 않은 형식"이라는 C2027 에러
- "Expected PlayerCharacter.h to be first header included" 에러
- `Implements<UInteractable>`에서 IDE가 E0300("바인딩된 함수 포인터는 호출에만 사용 가능") 경고

### **해결 방법**
- `BlueprintNativeEvent`로 선언한 함수는 `.cpp`에 반드시 `_Implementation` 접미사를 붙여서 정의해야 함 — `OnInteract` → `OnInteract_Implementation`으로 수정
- 이름을 고쳤는데도 같은 에러가 반복된 것은 UHT 캐시/증분빌드 문제로 추정 — 결과적으로 `.cpp`의 함수 정의 자체를 지우니 해결됨(블루프린트 전용 구현으로 남긴 것으로 판단)
- 헤더에는 전방 선언(`class USpringArmComponent;` 등)만 있고 실제 include가 없어서 발생 — `.cpp`에 `#include "GameFramework/SpringArmComponent.h"`, `#include "Camera/CameraComponent.h"`, `#include "Components/SphereComponent.h"` 추가
- UE 컨벤션: `.cpp`의 첫 include는 반드시 자기 자신의 헤더여야 함 — `#include "Player/PlayerCharacter.h"`를 맨 위로 이동
- `Implements<UInteractable>` 뒤에 괄호 `()`가 빠져서 함수 호출이 아니라 함수 포인터로 해석됨 — `Implements<UInteractable>()`로 수정

### **배운 점**
- BlueprintNativeEvent 관련 규칙이 두 가지로 나뉜다는 것: 정의할 때는 `_Implementation`, 호출할 때는 `Execute_` 접두사
- UE 헤더/cpp 관례(첫 include, 전방선언과 실제 include의 역할 분리)를 지키지 않으면 겉보기엔 사소한데 빌드가 막히는 경우가 많음
- Enhanced Input의 BindAction에 함수를 넘길 때 `&클래스::함수이름`처럼 괄호 없이 "주소"만 넘겨야 하고, 괄호를 붙이면 "지금 당장 호출"하는 것으로 오해되어 문법 오류가 남

### 오늘 배운 점 (TIL)
### **알게 된 내용:**
- UE 인터페이스는 `UInterface`를 상속하는 U접두사 껍데기와, 실제 함수가 선언되는 I접두사 진짜 인터페이스가 쌍으로 존재함
- `BlueprintNativeEvent` 함수 정의/호출 규칙: 정의는 `이름_Implementation`, 호출은 `I인터페이스::Execute_이름(대상, 인자...)`
- 콜리전 오버랩 이벤트(`OnComponentBeginOverlap`)에 함수를 연결하려면 `AddDynamic` 매크로 사용, 델리게이트에 연결되는 함수는 `UFUNCTION()` 필요
- `ETriggerEvent`는 상황에 따라 다르게 씀 — 계속 눌려있는 동안 반응해야 하면 `Triggered`, 누르는/떼는 순간만 반응해야 하면 `Started`/`Completed`
### **헷갈렸던 점**
- 헤더의 전방 선언만으로 충분한 경우와 실제 `#include`가 필요한 경우의 구분 — "포인터 선언만" vs "실제 함수 호출/객체 생성"이 기준이라는 것을 이번에 명확히 이해함
- `Implements<T>()`가 괄호 없이 쓰이면 함수 포인터로 해석된다는 점 — 템플릿 함수도 일반 함수처럼 괄호를 붙여야 "호출"이 된다는 걸 놓치기 쉬움
**예제 코드 또는 상황**

cpp

```cpp
// .h — 필요한 경우 코드 작성
// .h — PlayerCharacter.h (상호작용 관련 선언부)
UPROPERTY()
AActor* CurrentInteractable;

UFUNCTION()
void OnOverlapBegin(UPrimitiveComponent* OverlappedComp, AActor* OtherActor, UPrimitiveComponent* OtherComp, int32 OtherBodyIndex, bool bFromSweep, const FHitResult& SweepResult);

UFUNCTION()
void OnOverlapEnd(UPrimitiveComponent* OverlappedComp, AActor* OtherActor, UPrimitiveComponent* OtherComp, int32 OtherBodyIndex);
```

cpp

```cpp
// .cpp — 필요한 경우 코드 작성
// .cpp — 직접 작성한 상호작용 흐름
void APlayerCharacter::OnOverlapBegin(UPrimitiveComponent* OverlappedComp, AActor* OtherActor, UPrimitiveComponent* OtherComp, int32 OtherBodyIndex, bool bFromSweep, const FHitResult& SweepResult)
{
	if (OtherActor && OtherActor->Implements<UInteractable>())
	{
		CurrentInteractable = OtherActor;
	}
}

void APlayerCharacter::OnOverlapEnd(UPrimitiveComponent* OverlappedComp, AActor* OtherActor, UPrimitiveComponent* OtherComp, int32 OtherBodyIndex)
{
	if (OtherActor == CurrentInteractable)
	{
		CurrentInteractable = nullptr;
	}
}

void APlayerCharacter::Interact()
{
	if (CurrentInteractable != nullptr)
	{
		IInteractable::Execute_OnInteract(CurrentInteractable, this);
	}
}
```
