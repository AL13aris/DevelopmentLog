### 발생한 문제 & 해결 방법

### **문제 상황**
- 함선이 물 위에서 통통 튐
- LLM 리팩토링(맥락 축약) 직후 quest_text에 영어가 섞이거나 의미 없는 문장이 나옴
- `ABaseNPC.cpp`에서 `OnInteract_Implementation(AActor* Instigator)`의 파라미터 이름이 `AActor`의 기존 멤버 `Instigator`와 충돌(C4458)

### **해결 방법**
- 통통 튐: 블루프린트 `Buoyancy` 컴포넌트와 C++ `Tick()`의 수동 보정 로직이 동시에 위치를 제어하고 있는 게 원인으로 진단, `Tick()` 쪽 로직을 삭제하도록 서민규에게 전달(다음 확인 예정)
- 영어 섞임: 축약됐던 프롬프트에 맥락 설명(상황, 예시, "한국어로만" 명시)을 다시 보강해서 해결
- 파라미터 이름 충돌: `Instigator` → `InstigatorActor`로 이름 변경하여 해결. `IInteractable.h`와 이를 구현하는 모든 클래스에서 이름을 통일해야 함을 확인

### **배운 점**
- 블루프린트에서 추가된 컴포넌트는 C++ 코드만 봐서는 존재 여부를 알 수 없다는 것 — "코드에 없다 = 기능이 없다"고 단정하면 안 되고, 블루프린트 자식 클래스까지 확인해야 정확한 진단이 가능함
- LLM 프롬프트를 리팩토링할 때 길이를 줄이면 토큰/속도 이득은 있지만 맥락 손실로 품질이 떨어질 수 있어, 구조를 바꿀 때도 "정보량"은 유지해야 한다는 것
- `AActor`가 이미 `Instigator`라는 멤버를 갖고 있다는 것 — 인터페이스 함수의 파라미터 이름을 지을 때도 엔진 기본 멤버와의 충돌을 항상 먼저 체크해야 함(전에 `TakeDamage` 때도 비슷한 사례가 있었음)
