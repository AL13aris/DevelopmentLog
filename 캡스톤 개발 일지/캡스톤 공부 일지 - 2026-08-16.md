### 발생한 문제 & 해결 방법

### **문제 상황**
- `Water` 모듈을 `Build.cs`에 추가하지 않은 상태에서 `UBuoyancyComponent`를 헤더에 선언 → UHT가 생성한 `ShipBase.gen.cpp`에서 `WATER_API` 매크로 미정의로 인한 연쇄 에러 (`E0842`, `C4430`, `C2146`, `C2065`, `C2737`, `MSB3073`)
- `ACannonballProjectile`을 헤더에서 전방 선언만 해두고 `TSubclassOf<ACannonballProjectile>` `UPROPERTY`로 선언 → `UHT001: Unable to find 'class' with name 'ACannonballProjectile'`
- 바람 액터(`AWindDirectionalSource`) 헤더 경로를 처음에 `GameFramework/WindDirectionalSource.h`로 잘못 안내 — 실제로는 `Engine/WindDirectionalSource.h`

### **해결 방법**
- `GameCapstone.Build.cs`의 `PublicDependencyModuleNames`에 `"Water"` 추가 → 에디터/IDE 종료 → `Intermediate`/`Binaries` 삭제 → `.uproject`에서 "Generate Visual Studio project files" 재실행 → 재빌드로 해결
- `ACannonballProjectile`을 실제 `UCLASS()`로 선언한 최소 스텁(`AActor` 상속, 빈 생성자)을 먼저 만들어서 UHT가 클래스 존재를 인식하도록 함
- 중복된 `Super::BeginPlay();` 한 줄 제거
- 사용자가 프로젝트 내 실제 `WindDirectionalSource.h` 파일 내용을 직접 공유 → include 경로를 `Engine/WindDirectionalSource.h`로 정정

### **배운 점**
- 일반 C++ 포인터 멤버는 전방 선언만으로 충분하지만, `UPROPERTY`가 붙은 `UCLASS`/`TSubclassOf<T>` 타입은 **UHT의 별도 리플렉션 시스템**이 실제 클래스 정의를 요구하므로 전방 선언만으론 부족함 — 아직 구현이 없는 클래스를 참조해야 한다면 최소 스텁이라도 `UCLASS()`로 먼저 만들어야 함
- `Build.cs`에 모듈을 추가한 뒤에는 에디터 재시작만으로 부족할 수 있고, `Intermediate`/`Binaries` 삭제 + 프로젝트 파일 재생성까지 해야 확실하게 반영됨
- 엔진이 제공하는 클래스의 정확한 include 경로/API는 기억에 의존하지 말고, 실제 엔진 소스(Go to Definition)로 확인하는 게 가장 확실함

### 위험 요소 / 리팩토링할 부분
- `AShipBase::Tick()`의 토크 계수(`500000.f`), `UpdateAnchorProgress()`의 하강 깊이(`800.f`), `ACannonballProjectile`의 초기 속도(`3000.f`)/중력 스케일(`0.5f`) 등은 전부 임시값 — 실제 플레이 테스트하며 튜닝 필요
- `ApplyDamage_Implementation()` / `OnDestroyed_Implementation()`은 아직 빈 함수 — 데미지 반영, 침몰 연출 등 미구현
- 닻 진행도용 `AnchorCurve`(`UCurveFloat`) 에셋이 아직 에디터에 생성되어 있지 않음 — 만들지 않으면 `DropAnchor()`/`RaiseAnchor()`가 그냥 무시됨
- `ACannonballProjectile`을 부모로 한 블루프린트(`BP_Cannonball`)와 `ProjectileClass` 등록이 아직 안 되어 있어, 지금 상태로는 함포를 쏴도 아무것도 스폰되지 않음
- `APlayerShipPawn`(카메라 줌, 입력 바인딩, `OnInteract_Implementation`, `BoardShip()`/`ExitShip()`)은 아직 손대지 않음
- 적 AI 함선 설계는 기획서에 없는 영역이라 아직 시작 전 — `AShipBase`를 상속받아 만들 예정

### 오늘 배운 점 (TIL)
### **알게 된 내용:**
- `FTimeline`은 블루프린트와 달리 C++에서는 자동으로 재생되지 않고, `Tick()`에서 매 프레임 `TickTimeline(DeltaTime)`을 직접 호출해줘야 함
- `FTimeline`을 쓰려면 `BeginPlay()` 등에서 `FOnTimelineFloat` 델리게이트를 `BindUFunction()`으로 만들고 `AddInterpFloat(Curve, Delegate)`로 커브 에셋과 콜백 함수를 바인딩해야 동작함
- `AWindDirectionalSource`는 `UWindDirectionalSourceComponent`를 내부에 갖고 있고, `GetComponent()`로 꺼내면 `Strength` 같은 실제 바람 세기 값에 접근 가능
### **헷갈렸던 점**
- "포인터 멤버는 전방 선언만으로 충분하다"(6.1 트랩 노트)는 원칙이 `UPROPERTY`가 붙은 `TSubclassOf<UCLASS타입>`에도 그대로 적용될 줄 알았는데, UHT 리플렉션 단계에서는 실제 클래스 정의를 요구해서 `UHT001` 에러로 이어짐 — 일반 C++ 컴파일 규칙과 UHT 리플렉션 규칙이 다르다는 걸 이번에 명확히 구분하게 됨
