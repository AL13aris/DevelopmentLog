### 발생한 문제 & 해결 방법

### **문제 상황**
- `USTRUCT(BlueprintCallable)`로 잘못 지정 — `BlueprintCallable`은 함수용 지정자였음
- 마법사로 생성한 파일에 원래 있던 빈 클래스 껍데기(`class GAMECAPSTONE_API StarizonTypes { GENERATED_BODY() ... }`)를 안 지우고 그 위에 USTRUCT를 추가해서 `error C4430` 발생
- `FQuestData` 이름이 예전에 LLM 파이프라인 검증용으로 만들어뒀던 구조체와 겹쳐서 "shares engine name" 에러
- `GetItemCount()` 구현 중, const 함수 안에서 `FindByPredicate` 결과를 `FItemSlot*`(non-const)로 받으려다 "형식의 엔터티를 초기화할 수 없음" 에러
- `StarizonGameInstance.h`에 `ActiveQuests` 멤버 추가하는 과정에서 UHT가 "Member variable declaration: Expected name" 에러 (73번째 줄)

### **해결 방법**
- `USTRUCT(BlueprintType)`로 수정 — 구조체를 블루프린트 변수 타입으로 쓰게 하는 지정자
- 마법사가 자동 생성한 클래스 껍데기 전체 삭제 + `#include "StarizonTypes.generated.h"` 추가
- 예전 검증용 `FQuestData`/`FRewardItem` 선언을 파일에서 완전히 제거 (주석 대신 삭제로 정리, 의존하던 곳 있었으나 LLM 관련 코드 전체 제거로 해결)
- `const FItemSlot* Existing = ...`으로 const 붙여서 해결 — const 함수 안에서는 멤버가 읽기 전용으로 취급된다는 것 이해
- `ActiveQuests` 선언부 문법 오류 수정 (꺾쇠괄호/세미콜론 누락 계열 문제로 확인, 재작성으로 해결)

### **배운 점**
- UE 클래스 생성 마법사는 UCLASS 계열만 지원하므로, USTRUCT/UENUM만 있는 파일은 "None"으로 생성 후 껍데기를 지우고 써야 함
- 콘텐츠 브라우저의 "C++ Classes" 트리는 UCLASS 기준으로 폴더를 표시하므로, USTRUCT/UENUM만 있는 폴더(`Player`)는 트리에 안 보일 수 있음 — 실제 빌드에는 영향 없는 표시상의 특성
- `const` 함수 반환 타입 앞뒤 `const`의 역할이 다름: 앞쪽은 "반환값 수정 불가", 뒤쪽은 "이 함수는 멤버를 안 바꾼다는 선언"
- `TArray`의 `FindByPredicate`(첫 원소 찾기), `RemoveAll`(조건에 맞는 것 전부 삭제), `FilterByPredicate`(조건에 맞는 것만 새 배열로) 세 가지가 전부 같은 람다 패턴으로 쓰인다는 것
- 인벤토리처럼 매번 값이 바뀌는 런타임 데이터는 구조체로, 교역품처럼 고정된 기획 데이터는 DataTable Row로 구분해서 관리한다는 설계 원칙

### 오늘 배운 점 (TIL)
### **알게 된 내용:**
- `USTRUCT`/`UENUM`도 `UCLASS`처럼 `.generated.h` include가 반드시 필요하다는 것
- `UPROPERTY(BlueprintAssignable)`로 선언한 델리게이트는 새로 선언할 필요 없이 헤더에 있는 멤버를 그대로 `.Broadcast()`로 호출하면 된다는 것
- `GameInstance` 자체 멤버(`ActiveQuests`)와 서브시스템에 있는 데이터(`Inventory`)는 세이브 시 접근 방식이 다름 — 전자는 바로 대입, 후자는 `GetSubsystem<>()`으로 꺼내서 getter/setter 경유
### **헷갈렸던 점**
- `RemoveAll`이 왜 필요한지, 어디서 온 함수인지 처음엔 이해가 안 됐음 — `TArray`가 기본 제공하는 멤버 함수라는 것, `Add`/`FindByPredicate`와 같은 급의 기능이라는 걸 알고 나서 이해됨
- const 함수의 앞/뒤 const가 각각 뭘 의미하는지 헷갈렸는데, "반환값 수정 불가" vs "함수 자체가 안 바꿈"으로 구분하고 나서 명확해짐
**예제 코드 또는 상황**

cpp

```cpp
// .h — 필요한 경우 코드 작성
UFUNCTION(BlueprintPure) 
int32 GetItemCount(FName ItemID) const; 

UFUNCTION(BlueprintPure) 
const TArray<FItemSlot>& GetAllItems() const; 

UFUNCTION(BlueprintCallable) 
void SetAllItems(const TArray<FItemSlot>& InItems);
```

cpp

```cpp
// .cpp — 필요한 경우 코드 작성
void UInventorySubsystem::AddItem(FName ItemID, int32 Qty, bool bIsTradeGood) 
{ 
	if (Qty <= 0 || ItemID == NAME_None) 
	{ 
		return; 
	} 
	FItemSlot* Existing = Items.FindByPredicate([ItemID](const FItemSlot& Slot) 
	{ 
		return Slot.ItemID == ItemID; 
	}); 
	if (Existing != nullptr) 
	{ 
		Existing->Quantity += Qty; 
	} 
	else 
	{ 
		FItemSlot NewSlot; 
		NewSlot.ItemID = ItemID; 
		NewSlot.Quantity = Qty; 
		NewSlot.bIsTradeGood = bIsTradeGood; 
		Items.Add(NewSlot); 
	} 
	OnInventoryChanged.Broadcast(); 
}
```
