## 개발 일지 & TIL

**적 함선 피격 시험, 로비 수영 진단과 중간 발표 정리**

### 기본 정보

- 날짜: 2026-10-28 (한국시간)
- 프로젝트: Starizon Light / GameCapstone
- 기록 성격: 사용자 피격 확인·진단·발표 정리

### 오늘 한 작업

- 사용자가 생성한 EnemyShipPawn.h/.cpp에 AShipBase를 상속한 적 함선 기본 클래스를 구현했다. 공통 선체·부력·함포·피해·1회 파괴 처리를 재사용했다.
- 게임 월드 최초 초기화에서 시작 체력600, 적 전용 전투 레벨0, 생성 위치 HomeTransform을 설정하고 BP 체력·최대 체력·비율·복귀 기준 조회를 노출했다.
- 적 명중률은 플레이어 GameInstance의 전투 레벨을 읽지 않고 적 레벨만 사용하도록 구현했다.
- 후속 AI용 추격 제한30초·복귀 허용 반경10m·초당회복15를 조정 가능한 시험값으로 추가했다. 이 값만 추가했으며 실제 AI 동작은 구현하지 않았다.
- 이후 사용자 에디터 시험에서 플레이어 배와 적 배의 물리·부력·질량·무게중심을 비교하고, 더 낮게 뜨는 적 배의 폰툰 높이를 조정했다.
- 로비에서 메인맵으로 진입하면 수영하지 못하지만 메인맵 직접 PIE에서는 수영하는 차이를 조사했다. 당시 로그·코드 진단에서 Kingdom 항구 복원 실패와 복원 대기 상태를 확인했다.
- 중간 발표를 약 10분 분량으로 재구성하고 공지 기준 v5 PPT와 대본을 정리했다. 공유용 v11 HTML에도 진행 상태를 반영했다.
- 발표 피드백을 받은 뒤 다음 발표 자료를 HTML 슬라이드로 만들기로 정했다. 넓은 바다 항해 영상으로 시작하고 LLM과 게임 그래픽을 중심에 두며, 화면 글은 한두 줄과 가로 흐름으로 줄이는 방향을 기록했다.
- 추가 피드백을 반영해 '필요성 → 대표 목적 → 할 일 세 가지 → 플레이 흐름·현재 결과 → 향후 방향 → 가치와 필요성'의 설명 구조를 정리했다.
- 섬마다 다른 시세와 이벤트에 따른 교역 차익은 구현 예정으로 표시하고, 새 발표 자료의 실제 제작은 보류했다.

### 발생한 문제 & 대응

- 부모 자동 AI 빙의보다 먼저 초기 체력을 준비하고, 반복 초기화나 이미 파괴된 배에서 HP를 되채우지 않도록 초기화 순서와 가드를 검토했다.
- C++ 부모를 공유해도 플레이어 BP의 메시·충돌·부력·포문 에셋 설정이 새 적 BP에 자동 복사되지는 않는다.
- 같은 폰툰 좌표와 유사한 물리 설정에서도 적 배가 더 낮게 떠 보였다. 스크린샷 비교만으로 단일 원인을 확정하지 않고 폰툰 위치를 조정했다.
- 당시 이어하기 로그에 PendingPortRestore=1과 복귀 바닥 미검출이 나타났다. 복원이 끝나지 않으면 수영 전환도 보호 조건에 막히므로 수영 코드 자체와 진입 상태를 구분했다.
- 발표가 글과 세부 기능 나열 위주여서 전체 게임 흐름과 LLM의 차별점이 잘 드러나지 않는다는 피드백을 받았다.

### 확인 결과와 검증 범위

- 실제 함수10개를 추출한 독립 C++ 13개 시나리오에서 초기화·사망·무효 설정·체력 비율·적 명중률을 확인했다.
- 항구 판정·플레이어 배 복원·통 스포너 추적 대상이 APlayerShipPawn으로 제한됨을 정적 확인했다.
- 후속 사용자 대화에서 폰툰 조정 후 “대강 된거 같아”라고 부유 상태 개선을 보고했다. 정밀한 동일 흘수·장시간 안정성 검증은 아니다.
- 한국시간10월28일04:01 사용자 “줄어들고 사라지는 것까지 되네”로 적 함선 체력 감소와 제거를 확인했다. 이는 폴더 작업 기록의 앞선 PIE 대기 상태 이후의 사용자 시험 확인이다.
- 수영 문제는 당시 로그·코드 비교를 통한 원인 진단과 배치 수정 안내까지다. PlayerReturnBox 조정 후 수영이 복구됐다는 확인은 이 기록에서 찾지 못했다.
- 기존 v5 PPT·대본, 공유용 v11 HTML과 발표 피드백 MD가 남아 있다. HTML의 오프라인 점검 기록은 웹 문서 검증이며 게임 전체 실행 시험은 아니다.
- 피드백 이후의 발표용 HTML·새 대본·영상은 방향만 정했으며 제작 완료로 기록하지 않았다.

### 당시 남은 문제 / 미확인 사항

- 자동 플레이어/AI 빙의는 기본 Disabled이며 표적 선택·추격·공격·복귀·점진 회복은 없다.
- 전투 중 하선/입항 금지·동시파괴 플레이어 패배·게임오버/복귀는 후속이다.
- 복원 실패를 숨기려고 bPendingPortRestore를 강제로 풀면 저장·입항 보호도 해제된다. 복귀 박스 아래면과 보행 가능한 바닥 충돌부터 바로잡아야 한다.
- 실제 발표용 항해·LLM 영상 파일과 길이는 확인되지 않았다. 이미 영상을 확보하거나 연속 게임 루프 전체를 시연했다고 표현하지 않는다.
- 적 함선 시험 장면·해결된 버그·날짜별 완성 일정표의 제외 요청은 발표에 적용한다. 개발 일지에는 실제 작업 및 오류 해결 이력을 남긴다.

### 다음 작업 — 당시 기준

- 단일 적 피격·제거 확인을 바탕으로 AIController/BT/해역 관리자의 표적 선택·추격·공격·복귀·점진 회복을 연결한다.
- 폭발 이펙트와 침몰 연출은 나중 작업으로 남겼다.
- Kingdom의 PlayerReturnBox 아래면 중앙을 실제 보행 가능한 부두 충돌에 맞추고, 로비 이어하기에서 PortRestore Restored와 Surface swimming 로그를 순서대로 확인한다.
- 발표 제작 재개 시 실제 항해·LLM·회수 영상 보유 상태부터 확인하고 약 10분의 영상 포함 흐름과 대본을 구성한다.

### 오늘의 기술 정리 (TIL)

- 체력 정보의 기준을 공통 CombatComponent 하나로 유지하고 적 상태 조회를 노출하면 중복 피해·사망 상태를 만들지 않을 수 있다.
- 초기화 순서는 자동 Possess 같은 부모 콜백까지 고려해야 한다.
- 같은 맵이라도 직접 실행과 로비 이어하기의 저장·복원 상태가 다르다. 성공 경로와 실패 경로의 선행 상태를 비교해야 한다.
- 발표는 구현 목록보다 목적과 플레이어 행동·결과의 연결을 먼저 보여줘야 한다. 그래픽 에셋 사용, 자체 기술 구현, 구현 예정 기능도 구분한다.
